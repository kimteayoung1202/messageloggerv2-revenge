# Revenge All-in-One 0.5.6 — Revenge 1.11.6

0.5.6: 숨김 채널/권한 뷰어 설정의 행 전체를 누르면 켜기·끄기가 바뀝니다. 네이티브 Switch는 터치를 가로채지 않는 상태 표시로 사용하고, 접근성 switch 상태와 켜짐·꺼짐 글씨를 함께 표시합니다. 설정 저장과 채널 목록 갱신 경로를 유지합니다. 네이티브 스위치 이벤트 없이 원본 표시 모드의 설정을 끄고 다시 켜는 회귀 테스트를 추가했습니다. 실제 Android 터치 동작은 기기 확인이 필요합니다.

0.5.5: 요청한 cloudburst / Training Dummy의 [Hidden Channels Fix](https://github.com/trainingdummy/vendetta-plugins/tree/c473c13c1a5d7983d1fb45bda15fd19b14c21ead/plugins/hidden-channels)를 기준으로 표시 경로를 바꿨습니다. 커스텀 숨김 행 대신 Discord의 기본 채널 행으로 이름·기본 아이콘과 원래 위치를 사용하고 읽지 않음 상태를 별도로 억제하지 않습니다. 표시용 VIEW_CHANNEL 판정을 원본 방식으로 연결하되 실제 권한 판정은 따로 보존하여 권한 뷰어와 숨김 채널 판정에 사용합니다. 숨김 채널 메시지 요청과 transitionToGuild 이동을 막고, ChannelMessages 모듈이 발견되면 숨김 안내 화면을 표시합니다. 이 경로가 연결되면 기존 서버/종류 필터와 별도 카테고리 설정 대신 모든 서버의 받은 숨김 채널을 원래 위치에 표시합니다. All-in-One의 기능 켜기/끄기와 스트리머 모드는 유지합니다. 모듈이 아직 없으면 0.5.4 표시 경로를 유지합니다. 자동 테스트 242개 통과. 실제 Android 화면 결과는 아직 확인하지 못했습니다. 진단의 hiddenChannelStats.hiddenChannelsFix에서 permissions/router/fetcher/messages 및 nativeRows를 확인할 수 있습니다.

0.5.4: 숨김 채널 행에 목록에서 받은 ChannelRecord를 직접 전달하여 ID 재조회가 없거나 이름이 비어 있어도 받은 채널명을 표시합니다. 최신 저장소에 이름이 있으면 이름 변경도 반영합니다. 행 이름은 한 줄로 표시하고 긴 이름은 말줄임하며, 상세 화면에도 같은 이름 정보를 전달합니다. 메시지로거와 0.5.3의 목록 연결 경로를 유지합니다. 자동 테스트 235개 통과. 사용자가 0.5.3에서 숨김 채널이 나타나는 것을 확인했으며, 이번 이름 표시 수정의 Android 화면 결과는 아직 검증하지 못했습니다.

0.5.3: 0.5.2 기기 진단에서도 목록 저장소 탐색과 호출이 실패하여, 저장소 외에 ChannelListState의 getGuild / getGuildChannelRowsOnly에 직접 연결하는 경로를 추가했습니다. 늦게 초기화되는 모듈을 독립적으로 탐색하며 중복 목록 처리와 종료 후 패치 잔존을 방지합니다. 진단에 stateListCalls, rendererCalls, rendererSizeCalls와 입력 구조를 추가했습니다. 로거 기록 경로는 유지합니다. 자동 테스트 234개 통과. 실제 Android의 숨김 채널 표시는 아직 검증하지 못했습니다. 업데이트 후 앱을 다시 시작하고 서버 채널 목록을 열어 hiddenChannelList의 ChannelListState connected, hiddenChannelStats.stateListCalls 및 hiddenRowsRendered를 확인해 주세요.

0.5.1: 숨김 채널 렌더러 탐색을 실제 Vendetta 호환 API인 findByProps로 수정했습니다. Revenge 1.11.6의 Metro 내부에는 findByFilePath가 있지만 플러그인에 제공하는 vendetta.metro에는 없어 0.5.0의 렌더러 연결이 계속 탐색 중에 머물렀습니다. 숨김 채널 갱신 오류가 메시지로거 시작을 중단할 수 있는 경로도 수정했습니다. 로거를 먼저 연결하고 선택 기능의 오류와 알림 리스너의 오류를 격리하며, 채널 목록은 관련 설정이 바뀔 때 갱신합니다. 두 재현 테스트가 기존 코드에서 실패하고 수정 후 통과합니다. 자동 테스트 230개 통과. 진단의 loggerEvents는 실제 메시지 이벤트 수를, hiddenChannelStats는 목록 호출 수·캐시된 숨김 채널 수·표시 모델의 숨김 행 수·실제 렌더 호출 수와 모델의 키 구조를 보여줍니다. 실제 Android 실행과 사용자 기기의 정확한 오류는 검증하지 못했습니다.

기존 설치 링크로 업데이트할 수 있습니다. 메시지 기록과 설정 파일 경로를 그대로 사용합니다.

이전 내용만 작은 네이티브 subtext 수정 표시를 붙이고 회색 배경을 유지합니다. 네이티브 파서가 subtext 노드를 만들지 못해도 updateRows에서 보완할 수 있게 하며, 이미 이력을 붙인 행에 Discord의 마지막 수정 표시가 다시 들어와도 비웁니다. 진단에는 누적 시각 검사(nativeInputTimes/nativeRenderedTimes), ISO 변환 방법(nativeTimeObject), 감지 조건(nativeEditChecks), 실제 RowManager 이력 적용(nativeRowsHistoriesShown), 확인/표시 이력 개수(editProof)를 추가합니다. 실제 Android 화면에서 성공했는지는 아직 확인되지 않았습니다.

0.4.10: 실제 네이티브 화면 전송 경로인 `updateRows(viewId, serializedRows, ...)`도 연결합니다. RowManager/Flux/레코드 export가 호출되지 않는 경우에도 전송되는 메시지와 MessageStore의 원본 레코드를 비교하여 유효한 증가한 수정 시각이 있는 변경을 수집합니다. 이전 본문의 네이티브 AST를 관찰한 경우 그 노드를 보존하여 기존 서식을 유지합니다. 이전 내용마다 네이티브 subtext 접미사를 붙이고 회색 배경을 적용하며 마지막 수정 표시를 비웁니다. RowManager와 updateRows가 둘 다 처리하거나 같은 행을 재사용해도 이력을 중복 삽입하지 않습니다. 잘못된 JSON, 다른 데이터 형태, 전송 대기/실패 행은 원래대로 통과합니다.

현재 선택한 채널은 각 이벤트/네이티브 관찰 시 SelectedChannelStore에서 다시 확인합니다. CHANNEL_SELECT를 놓치고 시작 당시 채널만 계속 기록하는 경우를 방지합니다. 설정 첫 화면에 실제 updateRows/RowManager/레코드 갱신 호출 수를 표시하며 진단에는 nativeBridge, nativeBridgeCalls, nativeBridgeMessageRows, nativeBridgeStoreMatches, nativeBridgeHistoriesShown, stats를 추가합니다. 연결 발견과 실제 호출은 구분해야 합니다. 실제 347012 기기의 경로와 결과는 업데이트 후 진단으로 확인해야 합니다. 이전 본문을 관찰하지 못했거나 유효한 수정 시각을 얻지 못하면 이력을 만들지 않습니다.

0.4.9: 수정 이력을 같은 메시지 안에서 오래된 내용부터 현재 내용 순으로 표시하며 회색 배경을 적용합니다. 이전 버전에만 작은 회색 ` (수정됨)` 접미사를 붙이고, 마지막 내용의 `row.message.edited`는 null로 설정합니다. 네이티브 작은 표시는 Discord가 파싱한 subtext 노드를 이전 본문 바로 뒤에 넣습니다. 원래 edited 필드는 행 끝에 한 번만 표시하는 구조이므로 여러 과거 버전마다 같은 필드를 쓰는 것은 지원하지 않습니다. 네이티브 UI에서의 실제 크기와 줄 배치는 아직 기기 확인이 필요합니다.

수정 수집은 Flux 및 RowManager 관찰에 더해 `updateMessageRecord(oldRecord, newRecord)`의 교체 전 스냅샷을 이용합니다. 화면을 처음 그리기 전의 수정도 이전 본문과 유효한 증가한 수정 시각이 있으면 기록합니다. 확인된 수정 이력을 수정 시각 없는 렌더 입력 때문에 숨기는 경로를 제거합니다. 중복 Flux/레코드/렌더는 같은 이력을 추가하지 않습니다. 전송 대기와 실패 행 제외는 유지합니다. 진단에는 nativeRecords, nativeRecordUpdatesSeen, nativeRecordEdits, nativeRowsGenerated를 추가했습니다.

## 대상과 설치

대상은 Revenge **1.11.6 (`1b1d297-main`)**, Discord Android **347.12 (`347012`)**입니다.
Revenge의 해당 커밋에서 Vendetta 호환 로더와 API를 확인했습니다. Discord 347012의 실제 모듈 및 화면은 기기에서 검증하지 못했습니다.
0.3.0의 Next 전용 manifest와 진입점을 일반 Revenge용으로 교체했습니다.

1. `manifest.json`과 `index.js`를 같은 HTTPS 경로에 호스팅하세요.
2. Revenge 플러그인 URL 설치에 해당 디렉터리 주소를 넣으세요.
3. 플러그인 설정에서 기록과 연결 상태를 확인하세요.

ZIP 자체를 설치 URL로 쓸 수는 없습니다. GitHub 저장소에 배포 파일을 게시했습니다.
이전 배포물을 교체하려면 같은 설치 디렉터리에 두 파일을 함께 올리세요. manifest의 SHA-256 hash는 빌드할 때 갱신됩니다.
두 버전을 함께 켜지 마세요.

로더는 `onLoad`, `onUnload`, `settings`를 내보냅니다. 비동기 시작 중 끄기/다시 켜기는 순서대로 처리합니다.
메시지 처리는 FluxDispatcher의 dispatch를 통해 연결하고, 중지 시 해당 패치를 해제합니다.
파일 모듈은 해당 커밋과 같이 NativeFileModule / RTNFileManager / DCDFileManager를 탐색합니다.
파일 모듈이 없거나 로그가 손상됐으면 설정 화면에 시작 오류를 표시합니다.

## 기본 기록 범위

MLV2 기본값을 사용합니다. 현재 선택한 채널, DM, 화이트리스트를 기록하며 봇·차단 사용자·음소거 대상은 설정과 우선순위에 따라 제외됩니다.
모든 서버를 기록하려면 설정의 **모든 서버 기록 프리셋**을 선택하세요.

최근 전송 캐시는 기본 1,000개이며 세션 데이터입니다. 재시작 후에는 일반 전송 캐시가 없어지는 원본 동작을 따릅니다.
수정·삭제·일괄 삭제는 영구 로그로 저장합니다. 저장 한도는 각 카테고리당 기본 10,000개입니다.
한 메시지가 여러 카테고리에 있으면 오래된 기록을 지울 때 모든 카테고리에서 함께 제거합니다.
수정 이력의 표시 기본값은 5개이며, 숨겨진 버전도 디스크에 보존됩니다. 표시 제한이 저장 제한은 아닙니다.

실제 수정 시각이 없는 업데이트는 수정 이력에 넣지 않습니다. 링크 미리보기 갱신은 캐시의 임베드만 갱신합니다.
시스템 메시지, 전송 중인 임시 메시지, optimistic 메시지, ephemeral 응답은 원본 조건에 따라 제외됩니다.

## 기록 화면

최근 / 삭제 / 수정 / 일괄 삭제 / 고스트 핑 탭을 제공합니다.
삭제는 빨강, 수정 이전 내용은 회색입니다. 오래 누르면 숨기기, 색상 제거, 수정 표시 버전 선택, 개별 이력 삭제, 로그 제거 등의 메뉴를 엽니다.

검색 예:

```
guild:서버이름, channel:#일반, user:사용자이름, content:내용
has:image
has:link
message:메시지ID
```

쉼표로 연결한 조건은 모두 만족해야 합니다. 작성자 ID와 서버/채널 ID도 지원합니다.
원본 검색 문법에 더해 일반 텍스트 검색을 지원합니다.

`blockSpamEdit`의 원본 코드 조건은 설정 이름과 반대 방향입니다. 기본 OFF에서 같은 작성자의 1분 내 10번째 수정 알림부터 억제합니다.
이 구현은 그 실제 조건을 보존했으며 설정 화면에서는 **수정 알림 제한 해제**로 표시합니다. 이력 저장은 계속됩니다.

## 이미지·첨부

원본의 이미지 판별 범위인 JPG/JPEG/PNG/GIF/BMP를 삭제 저장 시 캐시합니다.
원본처럼 proxy URL을 우선 사용하고, 403/404는 재시도하지 않으며 기타 일시 실패는 최대 4회 시도합니다.
원본 MLV2는 모든 동영상을 로컬 저장하는 로직이 아닙니다. 영상·일반 파일 저장은 별도 확장 옵션으로 제공합니다.

모바일 구현의 차이:

- 한 파일 기본 8 MiB, 전체 기본 64 MiB. 설정에서 바이트 단위로 조정할 수 있습니다.
- 다운로드 1개씩, 대기열 64개, 요청 타임아웃 15초. 한도 초과 파일은 원본 링크만 유지합니다.
- Discord HTTPS 첨부 CDN만 다운로드하며 인증 토큰이나 쿠키를 전송하지 않습니다.
- Base64 JSON 캐시를 만들고, FileModule이 있으면 이를 실제 바이너리 파일로도 저장합니다.
- 캐시 이미지는 설정 화면에서 오프라인 미리보기를 제공합니다.
- 네이티브 바이너리 파일은 복원/갱신 메시지의 첨부 URI에 연결합니다. 실제 채팅 렌더러의 file URI 지원은 실기 확인이 필요합니다.
- 로컬 파일 공유는 기기의 공유 기능에 의존합니다. 동영상 오프라인 플레이어를 내장하지 않았습니다.

참조 없는 캐시를 정리하는 조건도 원본처럼 삭제 로그의 첨부를 기준으로 삼습니다. '참조 없는 이미지 유지'를 켜면 자동으로 지우지 않습니다.

## 저장·백업·가져오기

기본 저장 경로는 Discord 문서 폴더의 `message-logger/accounts/<사용자 ID>/`입니다.

- `archive-a.json`, `archive-b.json`: 번갈아 쓰는 로그 파일
- `settings.json`: 저장 금지 설정을 포함한 사용자 설정
- `backup.json`: 자동/수동 백업
- `media/index.json`, `media/<첨부ID>.json`: 첨부 캐시

원본과 같이 이벤트 저장을 약 1초 동안 합쳐 수행합니다. 자동 백업은 저장 후 약 20초 뒤 만듭니다.
앱이 백그라운드로 가거나 플러그인이 꺼질 때 저장을 시도합니다. 강제 종료 시 마지막 약 1초의 변경은 손실될 수 있습니다.
양쪽 로그가 손상됐으면 백업 복구를 시도하며, 복구도 불가능하면 기존 파일을 덮어쓰지 않고 시작을 중단합니다.

'디스크 저장 끄기'는 기록을 세션에서만 유지하며 설정 자체는 보존합니다. 다음 시작 시 기존 로그를 불러오지 않습니다.
현재 버전 0.2.0의 영구 로그를 읽을 수 있습니다. 기존 0.1.0의 `messages.json`은 자동 변환하거나 덮어쓰지 않습니다.
설정에서 원본 MLV2의 `data.messageRecord` 형식 또는 이 구현의 백업 JSON을 붙여 넣어 가져올 수 있습니다.
계정 ID가 있는 백업은 같은 계정만 가져옵니다.

## 0.4.2 모바일 연결 수정

- NativeFileModule 저장 형식은 그대로 유지합니다. 기존 로그를 지우지 않습니다.
- MessageRecord 프로토타입 getter와 editedTimestamp를 정규화합니다.
- 기존 본문과 다른 문자열을 가진 MESSAGE_UPDATE에 수정 시각이 누락됐으면 모바일 어댑터에서 시각을 보충합니다. 본문 없는 임베드 업데이트에는 적용하지 않습니다.
- MessageStore에서 찾지 못하면 네이티브 _channelMessages 캐시를 조회합니다.
- RowManager.generate를 추가 연결하여 수정 이력을 임시 표시 레코드에 넣습니다. 원래 MessageStore 본문 및 영구 로그에는 표시용 문자열을 저장하지 않습니다.
- 삭제 메시지는 빨간 배경/테두리, 수정 이력이 있는 메시지는 회색 배경/테두리를 적용합니다. 네이티브 행의 텍스트 span별 색상은 적용하지 않습니다.
- React MessageContent 경로는 삭제된 텍스트를 직접 빨간 Text로 표시합니다.
- 변경 뒤 재렌더링 이벤트를 예약합니다. 이 이벤트는 다시 기록하지 않습니다.

이 변경은 네이티브 경로의 모의 테스트로 검증했습니다. Discord 347012 실제 기기 검증은 여전히 필요합니다.

## 네이티브 연결의 한계

RowManager.generate 또는 MessageContent 경로로 채팅 표시를 연결합니다. MessageActionSheet와 ChannelHeader 등 export가 있어야 외부 메뉴를 연결합니다.
모듈이 없으면 설정의 기록 화면을 사용할 수 있으며, 채팅 삭제 이벤트를 무조건 차단하지 않습니다.
설정의 연결 상태에서 어떤 기능이 연결됐는지 확인할 수 있습니다.

실제 Android/Revenge 앱을 여기서 실행하지 못했습니다. 따라서 **모든 로직과 UI가 100% 동일하게 작동하는 완성 포트라고 보증하지 않습니다.**
데스크톱 DOM/CSS, 키보드 메뉴, localhost 이미지 서버는 모바일 구성으로 대체됐습니다.
원본 개발자의 업데이트 서버, 사용량 집계, 후원 UI는 포함하지 않습니다.

## 빌드·검증

추가 패키지 설치 없이 Node.js 18 이상에서:

```sh
npm run build
npm test
```

배포에 필요한 파일은 `manifest.json`, `index.js`입니다. ZIP에는 독립 소스, 테스트 입력/기대값, 비교 범위 문서를 함께 넣었습니다.
MLV2/BD 원본 소스 파일과 원본 실행용 비교 도구는 ZIP에 넣지 않았습니다. Hidden Channels Fix의 CC0 코드를 참고한 어댑터와 원본 저작권·라이선스 정보는 함께 제공합니다.

비교 기준: https://github.com/1Lighty/BetterDiscordPlugins/tree/master/Plugins/MessageLoggerV2
플랫폼 API 기준: https://github.com/revenge-mod/revenge-bundle/tree/1b1d297416594087769987908e5fc09af36b7e6e

0.4.3: React MessageContent와 기록 화면의 이전 본문은 opacity 0.7입니다. 네이티브 채팅의 문자 구간별 opacity는 아직 구현하지 않았습니다. 설정을 펼치면 nativeTextShape에 본문 값 없이 타입과 키 구조만 표시하여 기기의 렌더러 구조를 확인할 수 있습니다.

0.4.4: 설정 첫 화면에 버전과 연결 진단 보기/진단 복사 버튼을 표시합니다. nativeTextShape는 아직 수집하지 못했어도 항목을 표시합니다. RowManager default export를 명시적으로 해석하고 탐색 상태를 진단에 표시합니다.

0.4.4 수정 오인 방지: MESSAGE_UPDATE의 본문 차이만으로 수정 시각을 만들어 넣지 않습니다. edited_timestamp / editedTimestamp가 있는 실제 수정만 처리합니다. 0.4.1~0.4.3의 추론 동작은 제거했습니다. 이미 저장한 이력은 보존합니다.

0.4.5: 네이티브 진단의 앞 35개 필드 제한을 제거합니다. 본문/스타일 필드를 우선 탐색하며 최대 7단계 구조와 전체 최상위 키를 수집합니다. 문자열은 값 대신 타입만 표시합니다. 네이티브 이전 본문의 구간별 반투명 처리는 아직 적용하지 않습니다.

0.4.6: 모바일에서는 유효한 ISO 수정 시각을 가진 실제 수정 이벤트나 서버 로드로 확인된 이력만 표시합니다. 0.4.1~0.4.3의 추론 이력을 포함한 미확인 이전 기록은 삭제하지 않고 채팅/수정 목록에서 숨깁니다. 새 수정이 확인되어도 옛 미확인 버전까지 표시하지 않습니다. invalid_timestamp와 다른 로거의 __vml_restore_edit 이벤트는 수정 이력에 추가하지 않습니다.

네이티브 이전 본문의 라벨은 본문 아래 줄의 Discord subtext(-#)로 파싱하여 작은 회색으로 표시합니다. 각 버전을 별도로 파싱하여 코드 블록이 다음 버전/라벨을 감싸지 않게 합니다. 기본 수정 표시처럼 옆에 붙는 구간별 글꼴/opacity는 아직 지원하지 않습니다. 생성된 네이티브 행은 복사해서 수정하여 캐시 행의 하이라이트가 다른 메시지에 남지 않게 합니다. 실제 347012 화면 검증은 필요합니다.

0.4.7: 0.4.6에서 추가한 subtext 수정됨 줄을 제거합니다. 네이티브 row.message.edited의 기본 작은 표시만 사용합니다. 각 이전 버전 옆에 별도 작은 표시를 붙이는 기능은 아직 구현하지 못했습니다.

0.4.7 수정 감지 보완: RowManager 입력의 실제 본문과 editedTimestamp를 관찰합니다. Flux 이벤트가 없어도 앞서 관찰한 같은 메시지의 본문이 바뀌고 유효한 서버 수정 시각이 증가한 경우에만 기록합니다. 시간 없는 새로고침은 현재 본문 캐시만 갱신합니다. 단순 서버 로드로 옛 미확인 이력 전체를 수정 이력으로 인정하지 않습니다. 실제 이벤트/네이티브 관찰이라는 출처를 저장한 이력만 표시합니다. 네이티브 입력의 수정 시각 유무와 감지 횟수는 진단에서 확인할 수 있습니다.

0.4.8: 전송 대기 중인 회색 optimistic 행의 정리를 실제 삭제와 구분합니다. SENDING/SEND_FAILED 등의 상태, optimistic=true, 미확정 nonce 임시 ID는 기록하지 않습니다. MessageStore에서 가져온 임시 행도 제외하며 임시 행의 삭제/취소 이벤트는 차단하지 않습니다. 일괄 삭제에 임시/실제 ID가 섞여 있으면 임시 ID만 기본 처리에 전달합니다. SENT 상태의 실제 서버 메시지는 nonce가 있어도 정상 기록합니다.

state/nonce를 스냅샷에 보존하여 잘못 저장된 임시 로그를 다시 복원하지 않습니다. 임시 상태를 확인할 수 있는 기존 기록은 저널의 localTemporaryRecords에 격리해 보존하며 채팅에는 복원하지 않습니다. 메타데이터가 없는 오래된 기록은 임시 메시지인지 확정할 수 없습니다. 폰에서 실제 전송 대기 행이 제거되는지는 업데이트 후 검증이 필요합니다.
